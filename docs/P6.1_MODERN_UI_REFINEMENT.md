# P6.1 — Modern native Android UI refinement

P6.1 builds on the user-confirmed installed P6 app. Contemporary dashboards inform its visual hierarchy, but all UI remains native Jetpack Compose/Material 3. No other project or web source was inspected or modified. This phase does not change business rules, persistence, application ID, dependencies, or the P5.1 widget.

## Design direction and tokens

The app now has one high-emphasis progress hero, restrained supporting surfaces, compact status chips and a clearer navigation selection. Surfaces are used for meaningful groups rather than wrapping every number or journal row.

The existing centralized palette remains: primary maroon `#8B1717`, dark maroon `#5A1018`, gold `#D4A43A`, light background/surface `#F8F6F4` / `#FFFFFF`, dark background/surface `#171517` / `#252124`, and dark accent `#C94B50`. P6's readable secondary/action text roles remain. No wallpaper colors, additional font/icon libraries, gradients, or web UI dependencies are introduced.

`AppRefinement` adds 24 dp panel corners, 12 dp thumbnail corners, 1 dp supporting-surface elevation, and centralized hero roles. The hero uses dark maroon in both themes, white primary content, pale secondary content `#F4DDDF`, and a muted maroon progress track `#99545D`. Gold is limited to one small decorative rule in the hero. White hero text has approximately 13.8:1 contrast; secondary hero text approximately 10.68:1. Existing dark emphasized pill text against its maroon container measures approximately 4.70:1.

Page headings move to 28 sp / 36 sp with a small maroon header rule. Existing system sans-serif typography, 4/8/12/16/24/32 dp spacing, medium-weight headings and body text remain. Content is allowed to wrap and scroll; text is not shrunk to force a dashboard into a fixed phone viewport.

## Shared presentation components

- `RefinedSurface`: semantic Material surface, 24 dp corners, a 0.5 dp outline, zero tonal tint and 1 dp shadow. Used for supporting attendance summaries and settings groups.
- `StatusPill`: a non-interactive compact label with both text and an outline icon. Current/completed/pending/recovery labels come from existing screen/domain state; this component adds no attendance rules.
- `SettingsGroup`: a restrained surface and consistent section icon, with the existing editable settings/actions inside.
- `PhotoEvidence`: a rounded 64 dp preview with View photos and Share controls. It uses the same resolved file and callbacks, with bounded decoding and unchanged full-size evidence/photo selection.
- `RoundedProgress`: a rounded Canvas progress track with short animation and accessibility progress semantics. Actual text and announced values always reflect the existing recorded summary.
- Existing `TimelineRow`, `PageHeader`, `SettingsActionRow` and field colors are refined rather than replaced by separate screen implementations.

## Dashboard

The single dark-maroon hero contains OJT progress, the actual completed-hours value, required/remaining hours, percentage, a rounded progress track, and missing-goal access to Profile. Completed hours remain prominent. The existing `AttendanceCalculations.summary` result is unchanged.

Today's Attendance is a compact supporting surface with a status pill, recorded events/times, active-session information, resolution labels, morning/afternoon totals and the existing Open Attendance shortcut. It uses the same existing P5 status mapping. Recent activities remain a compact list, with refined thumbnails and View all access; there is no grid of repetitive statistic cards.

## Attendance

The date remains in the page heading. Completed-hour totals use one refined supporting surface. The four-event timeline now has larger but still compact indicators, a subtle connecting line, explicit status pills, and text timestamps. Recorded evidence is a compact thumbnail/action row instead of a wide image followed by disconnected buttons. Previous-day recovery has an explicit Action needed indicator.

The same `DailyAttendance.next`, busy state, earlier-open and legacy gates control the primary capture action. Skip/incomplete confirmation, legacy break handling, photo preview, timestamped sharing and audit warnings remain unchanged. No pending timeline row is a new attendance action.

## Activity journal and editor

Journal entries retain date grouping, actual titles/descriptions, counts and optional thumbnails. Their clickable area has a rounded ripple boundary, more comfortable row height and 64 dp rounded thumbnails; entries are not turned into stacked cards.

Add activity is a native floating primary button at the bottom end of the journal, above the existing bottom navigation. It retains the same callback and busy guards. The list reserves at least 104 dp and also measures the action's actual height to keep the final entry reachable at larger font sizes.

Existing filled fields receive consistent rounded shapes. The attachment section has a count pill and restrained per-attachment surfaces, keeping all view/reorder/remove controls. Required-field validation, dates/times, the five-photo limit, CameraX/Photo Picker handling, saved editor state, Save, discard/delete confirmation, sharing and persistence are unchanged.

## History

Dates use the existing readable date formatter. Duration totals have clearer hierarchy with a small history icon. Shared timeline chips/evidence rows give chronological records the same treatment as Attendance; resolution audit records have explicit status indicators. Date selection, ordering, legacy totals, daily calculations and missing-event explanations are unchanged.

## Profile/settings

A small profile identity header displays the existing saved name or a neutral Your profile label. Personal information, OJT requirements, Data & backup, and Application information use logical rounded settings groups with consistent small outline icons. Backup actions have compact icon surfaces and clear supporting descriptions.

All fields are supported by the existing model. Save validation, busy guards, offline export, restore validation preview and explicit REPLACE confirmation remain. There is no account/profile expansion or new stored field.

## Navigation, feedback and motion

All five destinations and widget shortcut routes remain. The bottom bar stays attached to the Android navigation area, with a rounded top edge, thin outline and restrained 3 dp elevation. The selected item now has a visible maroon-container pill and readable icon/text rather than relying on a text-color change alone. Existing selection semantics, restored tab state, loading/busy guards and Android safe-area handling remain.

Native Material ripples and navigation selection transitions provide interaction feedback. The only custom animation is the progress fill: a short 320 ms transition with Material easing on entry/value change. It does not animate numeric attendance totals or show intermediate values as if they were records. If `ValueAnimator.areAnimatorsEnabled()` is false, the fill uses a snap; Compose's platform animation-duration scaling also applies. There are no looping, attention-seeking, photo or navigation-content animations. Material/dialog behavior still needs verification with the A06's accessibility settings.

Dialogs retain the P6 Material shape/color system, scrollable content and explicit destructive-action confirmations. Editor field/attachment refinements appear inside the existing full-screen editor; dialog ownership, dismissal guards and camera lifecycle were not rewritten.

## Accessibility and responsiveness

- Text/status labels accompany all colored indicators. Decorative icons are not duplicated in accessibility descriptions.
- Existing Material buttons/icon controls retain practical 48 dp interaction targets; status pills and progress labels are display-only.
- Progress announces the true target fraction, not the briefly interpolated drawing. Actual hours remain textual and use existing formatting.
- Flow layouts, weighted text columns, scrolling forms, keyboard padding and safe drawing insets remain. The Add activity action's measured list inset protects the final row at larger fonts.
- Light and dark surfaces use existing semantic roles. Contrast-specific P6 ink colors are preserved; gold is decorative rather than small low-contrast body text.
- No launcher/widget styling, refresh worker or widget navigation code was changed.

## Samsung Galaxy A06 checklist

After a successful normal Gradle build, install an **in-place update with the same signing key**. Keep existing data. Do not uninstall, clear app storage, reset Room or restore over valuable records just to inspect the design.

- [ ] Open all five screens in light and dark mode. Confirm maroon remains the dominant accent, the hero is the only high-emphasis surface, gold is restrained, and supporting groups are readable without excessive boxes.
- [ ] Dashboard: compare completed, required, remaining and percentage against P6. Inspect zero goal, over-goal and nonzero-minute formatting with genuine/test data. Verify progress rounds correctly at 0%, partial and 100%; Open Attendance, Profile and recent-activity shortcuts must work.
- [ ] Attendance: inspect completed/current/pending/recovery chips, date/time hierarchy and evidence rows. Verify next-event capture gates, busy/duplicate-tap handling, legacy closure, skipped sessions and incomplete recovery using appropriate genuine attendance scenarios. Do not create artificial attendance to test colors.
- [ ] Open original/timestamped photos and share manually. Confirm the new evidence thumbnail does not affect original bytes, timestamp overlays or full-size viewing.
- [ ] Journal: inspect empty, long-title, no-photo and thumbnail entries. Scroll to the final row with the Add action visible, including large fonts. Open Add/Edit; exercise date/time selection, camera/picker round trips, five-photo limits, reorder/remove, full-screen viewing, Save and confirmed discard/delete.
- [ ] History: compare date order, times, daily/legacy totals and resolution audit entries. Verify evidence controls and scroll behavior on a larger history.
- [ ] Profile: confirm saved name/fields, validation, busy-state disabling, export and restore preview/cancel. Actual REPLACE testing should use a safe separate installation or explicitly prepared backup workflow, not valuable attendance data.
- [ ] Test default and larger font/display scaling, portrait/landscape, keyboard visibility, gesture and three-button navigation. Confirm the hero wraps readably, chips stay readable, all tabs remain identifiable, and no fixed action obscures the last row or system controls.
- [ ] Enable TalkBack: check page/section headings, selected tabs, status text, progress percentage, photo controls, action names and form errors. Non-interactive status chips should not act like buttons.
- [ ] Set Android Remove animations / animator duration scale off. Return to Dashboard and verify the progress fill appears immediately. Restore the normal setting and verify the animation is brief with no repeated looping or changing textual totals.
- [ ] Check every tab, Back, restored tab state and cold/warm widget Attendance/Activities shortcuts. The P5.1 widget's appearance, daily updates and refresh behavior must remain unchanged.
