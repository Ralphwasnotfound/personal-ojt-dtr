## Icon design rules

The existing `AppSymbol` code-native vector family is retained. All symbols share a 24 × 24 viewport, 1.8-unit outlined stroke, rounded line caps and rounded joins. No icon/font/network dependency or raster icon collection is added. New Save, Time In, Time Out, Calendar, Progress, Completed, Remaining, Backup, Info and Warning symbols extend the same vector family.

Sizes:

- 18 dp: compact action labels, status pills, small inline indicators and chevrons.
- 20 dp: ordinary icon-and-text actions and section indicators.
- 24 dp: icon-only controls and bottom navigation.
- Existing camera shutter: 84 dp circular target; its white disc is intentionally retained without an extra camera glyph.

Color comes from the containing Material component's content color, selected semantic role or the existing branded progress surface. `AppIcon` defaults to Material Icon's content tint. A neutral black vector path is a tint mask, not a fixed black screen color. Destructive actions use `colorScheme.error`, while disabled content is supplied by Material button colors. No hardcoded presentation colors were introduced.

## Reusable action components

`ActionLabel` pairs a decorative icon with visible text and consistent 8 dp spacing. Compact labels use 18 dp glyphs and ordinary actions use 20 dp. Text has flexible width so long labels can wrap rather than pushing the icon out of bounds.

`ActionIconButton` provides a 24 dp glyph, explicit content description and minimum 48 dp target. It supports enabled/disabled state and optional destructive error tint.

`DestructiveButton` pairs an error-colored symbol and label while letting Material mute both in the disabled state. Delete/discard use Delete; the existing data-replacement confirmation uses Restore. Existing confirmation dialogs and callbacks remain in place.

Existing QuietButton and SecondaryButton now have a minimum 48 dp visual height. Section headings and timeline markers accept optional symbols rather than adding icons to every body label.

## Screen-specific notes

### Attendance and History

Time In and Time Out are visual cues only, selected from the existing event type. The state machine, gating, available next action, recovery rules, validation and timestamps remain unchanged. Text continues to distinguish completed, available, pending, missing and recovery states; icons or color alone never communicate attendance validity.

The shared evidence row applies consistently in Attendance and History. History uses Calendar for date groups and Completed for the total, with existing recovery pills and legacy text preserved. No new history filtering behavior is invented.

### Activity Journal

Delete and photo removal are visually distinct and have explicit labels. Activity deletion retains its confirmation dialog. Cancel/discard retains the existing unsaved-change confirmation. Save, picker launches, photo ordering/removal and shares use the same original callbacks and enabled conditions. The five-photo maximum is unchanged.

The photo viewer's middle Share button has weighted width, reserving space for both 48 dp previous/next buttons when labels grow. The editor's date/time chooser now uses explicitly named icon buttons instead of ambiguous Choose text. The fields themselves remain editable, and the same date/time picker callbacks are used.

### Dashboard and Profile

Dashboard adds a few symbolic anchors around progress and section/actions; no icon is placed beside every number. Its name fallback, Profile shortcut, 72 dp unmodified BSIT logo, launcher work, progress arithmetic and routes are preserved.

Profile retains settings-style groups/rows and adds meaningful requirements, backup and application-info symbols. Save settings now has Save; Export/Restore/Appearance keep their existing leading icons and functionality.

### Camera and navigation

The P6.2 camera header already had 48 dp Close/Flash/Switch targets with accessible descriptions. Those controls and their logic are retained. Review and recovery actions gain compact icons; the shutter remains an uncluttered white circular capture control with its existing accessibility description and duplicate-request protection.

P6.3 behavior remains: live camera dark, review/permission/error supporting surfaces selected-theme aware. Bottom navigation keeps all five original routes, outlined icons, labels and selected state. No navigation callback is changed.

## Light/dark and accessibility checks

Source review checked:

- Paired icon-and-text actions have null icon descriptions, so the visible text names the action without duplicate icon announcements.
- Icon-only actions have explicit labels, including indexed move/remove controls, picker choice, viewer navigation and existing camera controls.
- Interactive icon controls have 48 dp targets; camera shutter/review controls retain their existing larger sizes.
- Material enabled/disabled content colors are retained, including destructive controls.
- Important attendance status, destructive meaning and recovery information remain visible as text.
- Shared action glyphs inherit semantic Material colors; branded Dashboard/camera exceptions inherit their established high-contrast content roles.
- Action labels wrap within available width, and viewer arrows have reserved space.

These are source-level checks. TalkBack behavior, actual touch exploration, contrast perception and font-scale layout have not been exercised on a device.
