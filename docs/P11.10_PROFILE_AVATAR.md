# P11.10 — Local profile photo and launcher branding

This is the historical P11.10 report. P11.11 moved photo editing into Edit Profile and updated launcher transparency; see [the P11.11 report](P11.11_ICON_AND_PROFILE_CONTROLS.md) for the current behavior.

Profile has Change Photo and Remove Photo actions. Android Photo Picker imports an image into temporary private cache; selection alone does not change the profile. A circular preview offers zoom and horizontal/vertical positioning. Confirm Photo writes the square crop; Cancel discards it. Profile and Dashboard collect the same reactive repository reference. Each retains its original placeholder when no readable avatar exists. The separate BSIT crest in Dashboard is unchanged.

## Storage and safety

- Source import is bounded to 20 MiB, 16,000 pixels per dimension and 80 megapixels.
- Existing EXIF-aware decoder normalizes orientation and downsamples the temporary preview to 1,024 pixels maximum edge.
- Confirmed images are 512×512 JPEG at quality 88 with transparency flattened onto warm white. A 2 MiB validation limit applies.
- Files live under private `files/profile-avatar/photos/<UUID>.jpg`. A synced atomic `profile-avatar/reference` file identifies the current immutable photo and restore generation. No image bytes, schema changes or gallery URI dependencies were added to Room.
- The previous photo remains active until the replacement reference commits. Cleanup removes obsolete avatar files only, and retries at startup if cleanup fails. Temporary picker/crop drafts are excluded from backup and cleaned on cancel/startup.
- Missing/corrupt images use the default avatar; their references can still be removed through Profile.
- ZIP format 5 adds an optional separate JPEG avatar asset; Room remains version 6. Formats 1–4 remain readable. Restore prepares an avatar sidecar before committing the existing Room generation marker. Older/no-photo backups restore the default avatar. Attendance and activity media remain separate.

## Launcher

The application label is `OJT Companion`; application ID remains `com.lazarus.personalojtdtr`. Manifest now supplies both regular and round adaptive icons. The existing transparent crest artwork is unchanged. Foreground inset changed from 25% to 22%, enlarging the artwork by 12%. Its measured alpha bounds remain within the adaptive safe circle (32.49dp maximum radius, versus 33dp safe radius on a 108dp layer). The launcher still applies its required neutral adaptive background and Samsung mask; a fully transparent final icon is not promised.
